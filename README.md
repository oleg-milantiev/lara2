# Laravel Отчёты цен продуктов

Реализован механизм формирования отчёта по товарам выбранной категории.
С минимальной и максимальной ценой за последние 7 дней.
С сохранением CSV-файла и ведением журнала выполнения процесса.
С возможностью последующего контроля и скачивания отчётов.

## Вопросы к ТЗ

### Шаблон выходного файла
**Проблема** Команда принимает category_id, но единственный выходной файл формируется с учётом и category_id (одна), и manufacturer_id (много).

**Предложенное решение** Исключил manufacturer_id из шаблона выходного файла.

### Строки цен в выходном файле
**Проблема** Присутствует Требование, в котором по каждому товару необходимо выводить две строки. С минимальной и максимальной ценой за период. Не определено поведение при отсутствии цены за продукт, при отсутствии изменений цен за неделю.

**Предложенное решение** Всегда вывожу 2 строки. Даже если цен на продукт нет вовсе. Можно изменить поведение.

### Учёт базовой цены (до недельного периода)
**Проблема** В ТЗ не указано, что делать, если не было изменений цены в течение последней недели. Или если изменение было лишь одно.

**Предложенное решение** Ввёл понятие базовой цены, то есть последней цены вне недельного окна. Использую его, если нет изменения цены в недельный период. 

**На обсуждение** Если есть хотя бы одно изменение, оно будет и минимальным, и максимальным (базовая цена не используется). Мне кажется, стоит учитывать базовую цену при этом.

## Основной функционал

### Страница контроля выполнения процессов
Доступна на главной странице проекта без авторизации.

Даёт доступ к таблице "Контроль выполнения процессов".
- дата процесса
- время запуска
- время выполнения
- идентификатор процесса
- статус процесса
- имя файла (гиперссылка для успешно оконченных процессов)

**Пагинация:**
Данные таблицы выводятся постранично, по 25 строк на страницу

### Команда формирования отчёта
Консольная команда app:report принимает обязательный параметр (int) category_id.
- генерирует CSV-файл, где дата/время в имени — это дата/время запуска команды, шаблон report_{manufacturer_id}_{category_id}_{ГГГГ-ММ-ДД_ЧЧ-ММСС}.csv;
- в отчете следующие столбцы: manufacturer_name, product_name, price, price_date;
- по каждому товару выводятся две строки, с минимальной и максимальной ценой за последние 7 дней от текущей даты;
- если для указанной категории нет товаров — выводится сообщение об ошибке;
- цена товара должна округлена до двух знаков после запятой.

## Технические детали
- **База данных:** PostgreSQL. Таблицы:
  - manufacturer: справочник производителей;
  - product: справочник продуктов с данными о категории и производителе;
  - price: история изменения цен продуктов;
  - report_process: текущие и исторические процессы экспорта;
  - process_status: справочник статусов процессов экспорта.
- **Кеш:** Redis.
- **Тесты:** Проект покрыт Unit и Feature тестами.
- **Данные:** База наполнена случайными тестовыми данными (~5_000 товаров в 5 категориях, ~15_000 цен до 4 знаков после запятой). Добавлена одна пустая категория (без продуктов).

Цены привязаны к продуктам. По 0..5 цен к каждому продукту. Даты цен для каждого продукта (могут быть не все. Может быть ни одной):
- 0..2 старых цен (до апреля 2026);
- 0..1 цена сегодняшняя;
- 0..2 цены 3 дня назад.

## Запуск в Docker

Предполагается размещение проекта в `/root/lara2` и наличие docker-compose.

Запуск окружения через docker compose up -d приведёт к:
- build php контейнера;
- pull nginx, redis и postgresql образов;
- запуску контейнеров.

Я запускаю проект в отдельной виртуалке VirtualBox с NAT и VirtualHost интерфейсами.
Доступ браузером получаю, прописав IP машины в hosts как lara2.local.
После чего веб доступен по http://lara2.local:88 (80 порт у меня занят на этом хосте).

Для запуска команд внутри контейнера использую:
```bash
cd /root/lara2 && docker compose exec -it php some-command
```

Путь к проекту внутри контейнера: `/var/www/lara`.

Для запуска проекта необходимо в php контейнере, в папке /var/www/lara, выполнить команды:
- ./artisan migrate:fresh
- ./artisan db:seed
